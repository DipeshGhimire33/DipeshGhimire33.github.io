Project 01 · Machine Learning

Sepsis prediction from ICU data

```

An end-to-end machine learning pipeline built using the public PhysioNet/CinC Challenge 2019 dataset. The project covers data exploration, cleaning, feature engineering, model comparison, and a Streamlit demo. It is an educational project, not a medical tool.

1,552,210 rows
Data from 40,336 ICU patients.
1.8% positive
Sepsis observations are rare, making accuracy alone misleading.
Up to 99.8% missing
Some laboratory measurements are rarely recorded.
Code and notebooks Written project summary
```

Where I made the call

```

The important part wasn't just training a model. It was checking assumptions, comparing alternatives, and making the limitations clear.

  • I made a data-handling decision

    Missing values

    I used forward filling within each patient rather than applying population-level median imputation to every missing measurement.

    This keeps the patient's last recorded measurement available until a newer one appears. It was a judgment call, not a method proven superior through comparative testing, and remains a limitation.

  • I checked the model choice

    Comparing five models

    I compared XGBoost against logistic regression, random forest, histogram gradient boosting, and linear SVM using consistent patient-level splits.

    XGBoost led on PR-AUC and ROC-AUC, while random forest performed slightly better on F1 and recall. I report multiple metrics instead of relying on a single score.

  • Safeguard

    Splitting by patient, not by row

    70% of patients for training, 10% for validation, and 20% for testing.

    This helps prevent rows from the same patient appearing in both training and testing, which could make performance appear better than it really is.

  • Safeguard

    Choosing the alert threshold

    I selected a threshold of 0.80 using validation data and applied it unchanged to the test set.

    Using the test set to tune a threshold would compromise its role as an independent evaluation.

```

What the model actually achieves

```
Held-out test set · Patient-level split
Model PR-AUC ROC-AUC
XGBoost 0.0929 0.7913
Random forest 0.0912 0.7876
Histogram gradient boosting 0.0889 0.7864
Logistic regression 0.0734 0.7433
Linear SVM 0.0715 0.7440

The result is modest. A random-ranking baseline would have a PR-AUC near the positive-class prevalence, approximately 0.019 on this test set.

What it can't do

  • At the selected threshold, recall is 0.249 and precision is 0.136.
  • It has not been validated on another hospital or population.
  • The reference ranges used in the engineered features are heuristic, not clinical standards.
  • The strongest feature was time in the ICU; that describes model behaviour, not causation.
  • It is not intended for diagnosis or treatment decisions.

Project 02 · Data Analysis

Understanding cybercrime reporting in Nepal

```

An exploratory data analysis project examining reported cybercrime patterns in Nepal. Rather than relying on one unified dataset, I collected and consolidated aggregate data from multiple sources to study reporting trends, cybercrime mediums, victim groups, and provincial patterns.

3 fiscal years
Cybercrime reporting data from 2022/23 to 2024/25.
Multiple sources
Reporting, cybercrime medium, victim-group, population, and literacy data.
Data validation
Cross-dataset checks to identify discrepancies instead of silently changing totals.

What I investigated

  • Annual changes in reported cybercrime applications.
  • Reported cybercrime mediums, including social media, messaging applications, and digital financial services.
  • Differences in reported cases across victim groups.
  • Provincial reporting patterns alongside population and literacy indicators.
  • Consistency between totals reported by different datasets.

From fragmented data to analysis

  • Data collection and consolidation

    Working across sources

    Collected cybercrime-related aggregate datasets covering reporting offices, mediums, victim groups, population, and literacy. Standardized categories and labels to support comparisons.

  • Data quality

    Checking the totals

    Compared annual totals across application, medium, and victim-group datasets. A five-case discrepancy appeared in the 2022/23 victim-group total, so it was documented rather than silently corrected.

  • Analytical judgment

    Not forcing machine learning

    I evaluated whether predictive modelling was appropriate. With only three annual observations for the main reporting trends and seven provinces for demographic comparisons, I concluded that the available aggregate data were insufficient for robust predictive modelling.

Tools and workflow

Python · Pandas · NumPy · Jupyter Notebook · Streamlit

The workflow covers exploratory data analysis, data preprocessing, feature engineering, comparative analysis, cross-dataset validation, and final findings.

Project repository Interactive Streamlit demo coming soon.

This is an exploratory analysis of reported aggregate data. Reporting patterns do not necessarily represent the true prevalence of cybercrime, and associations with population or literacy do not establish causation.
